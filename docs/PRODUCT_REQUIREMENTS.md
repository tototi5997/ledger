# 个人日常记账应用产品文档

## 1. 产品概述

本应用是一款面向个人日常使用的轻量记账工具。用户通过手机号登录后，可以快速记录日常收入和支出，并通过移动端 PWA 查看账目流水、月度统计、资金渠道统计、分类消费和个人收支趋势。

技术方案采用 Next.js + Supabase + PWA，并通过 Vercel 部署。产品优先保证低维护成本、数据可靠性、移动端体验和个人记账效率。

## 2. 产品目标

### 2.1 核心目标

- 支持个人快速记录日常支出和收入。
- 支持手机号登录，降低使用门槛。
- 支持为每笔收入或支出选择资金渠道，例如支付宝、微信、银行卡、现金。
- 支持为每笔收入或支出选择分类标签，例如餐饮、教育、工资、退款。
- 提供清晰的月度统计、资金渠道统计、分类统计和收支趋势。
- 支持按月份、资金渠道、分类标签和关键词查看历史流水。
- 支持手机浏览器安装为 PWA，接近原生应用体验。
- 使用 Supabase 管理认证、数据库和权限。
- 使用 Vercel 实现快速部署和持续发布。

### 2.2 非目标

- 不做复杂企业财务系统。
- 不做多币种复杂汇率核算，MVP 默认单一币种。
- 不做发票 OCR、银行流水自动导入等高级功能。
- 不做公开社交或跨账本社区功能。
- MVP 不做多人协作、AA 分账、成员邀请和成员间结算。
- MVP 不做预算管理。
- MVP 不做账户余额管理，资金渠道仅用于统计和筛选。
- MVP 不要求离线完整编辑能力，可优先支持基础缓存和弱网提示。

## 3. 用户与场景

### 3.1 目标用户

- 个人用户：记录每日餐饮、交通、购物、娱乐等日常支出。
- 有消费复盘需求的用户：希望了解每月钱花在哪里。
- 有复盘习惯的用户：希望按月查看收入、支出和结余变化。
- 移动端优先用户：希望像手机 App 一样快速打开和记账。

### 3.2 典型场景

- 用户早餐花费 18 元，资金渠道选择“支付宝”，分类标签选择“餐饮”。
- 用户收到工资 12000 元，资金渠道选择“银行卡”，分类标签选择“工资”。
- 用户收到微信红包 200 元，资金渠道选择“微信”，分类标签选择“红包”。
- 用户月底查看本月总支出、分类占比和结余。
- 用户想知道本月餐饮是否明显超支。
- 用户想知道本月支付宝收入多少、微信支出多少。
- 用户在手机主屏幕打开 PWA，快速新增一笔消费。

## 4. MVP 功能范围

### 4.1 账户与登录

- 用户可通过手机号 + 密码登录。
- 用户注册时使用手机号作为账号，并自定义密码。
- 登录后可创建个人资料，包含昵称和头像。
- 用户可退出登录。

### 4.2 账本管理

- MVP 默认每个用户拥有一个个人账本。
- 用户可设置账本名称、默认币种和描述。
- 用户只能查看和管理自己的账本数据。
- 后续版本可扩展多个账本。

### 4.3 成员管理

MVP 不包含成员管理。

后续如需要支持家庭或小团队账本，可再扩展成员、角色、邀请和结算能力。

### 4.4 交易记录

交易类型：

- 支出：如餐饮、交通、房租、购物。
- 收入：如工资、奖金、退款、红包。

交易字段：

- 金额。
- 日期。
- 资金渠道，例如支付宝、微信、银行卡、现金。
- 分类标签，例如餐饮、教育、工资、红包；每笔交易只能选择一个分类标签。
- 备注。
- 创建人。

MVP 可选字段：

- 附件图片，后续版本实现。

编辑规则：

- 用户可编辑自己创建的记录。
- 被编辑后记录更新时间。
- 删除采用软删除，避免误删后数据不可恢复。

### 4.5 资金渠道管理

MVP 内置默认资金渠道：

- 支付宝。
- 微信。
- 银行卡。
- 现金。
- 其他。

MVP 支持自定义资金渠道：

- 用户可新增资金渠道。
- 用户可编辑自己创建的资金渠道名称、图标和颜色。
- 用户可隐藏不常用资金渠道。
- 已被交易引用的资金渠道不能硬删除，可通过隐藏方式从新增交易选项中移除。

### 4.6 分类标签管理

MVP 内置默认支出分类标签：

- 餐饮。
- 交通。
- 住宿。
- 房租。
- 水电。
- 日用品。
- 娱乐。
- 医疗。
- 教育。
- 购物。
- 其他。

MVP 内置默认收入分类标签：

- 工资。
- 奖金。
- 退款。
- 红包。
- 兼职。
- 投资收益。
- 其他。

MVP 支持自定义分类标签：

- 用户可新增收入分类标签或支出分类标签。
- 用户可编辑自己创建的分类标签名称、图标、颜色和类型。
- 用户可隐藏不常用分类标签。
- 已被交易引用的分类标签不能硬删除，可通过隐藏方式从新增交易选项中移除。

### 4.7 结余计算

MVP 优先支持基础结余计算：

- 总收入。
- 总支出。
- 当前结余。
- 月度结余。

### 4.8 统计与报表

MVP 统计范围：

- 本月总支出。
- 本月总收入。
- 本月结余。
- 按资金渠道汇总收入和支出。
- 按分类标签汇总收入和支出。
- 收支趋势。
- 最近交易列表。
- 可按月份筛选。

### 4.8 PWA

PWA 能力：

- 可添加到手机主屏幕。
- 提供 App Icon、启动页和 manifest。
- 缓存基础静态资源。
- 弱网状态下显示友好提示。
- 后续可扩展离线记账草稿。

## 7. 权限与安全

### 7.1 权限原则

- 所有账本数据必须基于用户归属访问。
- 未登录用户不能访问任何账本数据。
- 用户只能读取、创建、修改和删除自己的账本数据。
- 管理后台或维护脚本不得绕过 RLS 读取普通用户数据，除非有明确运维需求。

### 7.2 Supabase RLS 策略

所有核心表建议开启 Row Level Security。

基础策略：

- `profiles`：用户只能读取和更新自己的资料。
- `ledgers`：用户只能读取和更新 `created_by = auth.uid()` 的账本。
- `funding_sources`：用户可读取系统资金渠道和自己账本下的资金渠道；用户只能新增、更新和隐藏自己账本下的资金渠道。
- `category_tags`：用户可读取系统分类标签和自己账本下的分类标签；用户只能新增、更新和隐藏自己账本下的分类标签。
- `transactions`：用户只能读取、创建、更新和软删除自己账本下的交易。

### 7.3 数据安全

- 不在前端暴露 Supabase service role key。
- Vercel 环境变量只配置必要的 public anon key 和 server-only key。
- 所有敏感写操作优先通过 Server Actions 或 Route Handlers 执行。
- 金额计算避免浮点误差，数据库使用 numeric，前端使用以分为单位的整数或 Decimal 类库。

## 8. 核心业务规则

### 8.1 金额规则

- 金额必须大于 0。
- 金额最多保留两位小数。
- 支出计入支出统计。
- 收入计入收入统计。
- 资金渠道仅用于统计和筛选，不计算账户余额。
- 每笔交易必须且只能选择一个分类标签。

### 8.2 统计规则

计算步骤：

1. 按月份汇总收入交易。
2. 按月份汇总支出交易。
3. 月度结余 = 月度收入 - 月度支出。
4. 按资金渠道汇总收入和支出，用于资金渠道图。
5. 按分类标签汇总收入和支出，用于分类占比图。
6. 按日期汇总收入和支出，用于趋势图。

### 8.3 删除规则

- 删除交易采用软删除。
- 软删除交易不参与统计。
- 资金渠道和分类标签被交易引用后不能硬删除。
- 资金渠道和分类标签支持隐藏，隐藏后不在新增或编辑交易的默认选项中展示，但历史交易仍正常显示。
- 后续可支持回收站和恢复。

## 9. 技术架构

### 9.1 前端

- Next.js App Router。
- TypeScript。
- React Server Components 优先。
- Server Actions 或 Route Handlers 处理写入。
- Tailwind CSS 或其他轻量 UI 方案。
- 表单建议使用 React Hook Form + Zod。
- 图表可使用 Recharts 或 Tremor。

### 9.2 后端与数据库

- Supabase Auth：登录认证。
- Supabase PostgreSQL：核心数据存储。
- Supabase RLS：行级权限控制。
- Supabase Storage：头像或附件，MVP 可暂不启用。
- Supabase Realtime：MVP 暂不需要，后续可用于多端实时同步。

### 9.3 PWA

- 使用 `next-pwa` 或基于 Workbox 的方案。
- 配置 `manifest.webmanifest`。
- 添加不同尺寸图标。
- 缓存静态资源。
- API 请求不做激进缓存，避免账目数据陈旧。

### 9.4 部署

- Vercel 部署 Next.js。
- Supabase 托管数据库和认证。
- 通过 GitHub 仓库连接 Vercel。
- Preview Deployment 用于测试分支。
- Production Deployment 用于主分支发布。

### 9.5 环境变量

建议变量：

```env
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
SUPABASE_SERVICE_ROLE_KEY=
NEXT_PUBLIC_SITE_URL=
```

注意：

- `SUPABASE_SERVICE_ROLE_KEY` 只能在服务端使用。
- 前端代码不能引用 service role key。

## 10. 用户体验要求

### 10.1 移动端优先

- 首页首屏必须展示本月收入、本月支出、本月结余和新增交易入口。
- 新增交易流程不超过 1 个主页面。
- 新增交易字段顺序固定为：交易类型、资金渠道、金额、分类标签、日期、备注。
- 金额输入应适配手机数字键盘。
- 资金渠道选择应支持常用渠道优先展示。
- 分类标签选择应支持常用标签优先展示。
- 日期默认使用当天。

### 10.2 空状态

- 无账本：自动创建默认个人账本，或提示初始化账本。
- 无交易：提示新增第一笔交易。
- 无统计：提示当前月份暂无数据。

### 10.3 错误状态

- 登录失败：提示手机号或密码错误。
- 手机号格式错误：提示输入有效手机号。
- 密码不符合要求：提示密码规则。
- 金额、资金渠道或分类标签缺失：阻止提交并提示补全。
- 网络错误：提示稍后重试。

### 10.4 性能要求

- 首屏加载目标小于 2 秒。
- 交易列表分页或按月加载，避免一次性加载大量数据。
- 图表数据在服务端聚合后返回。

## 11. 验收标准

### 11.1 MVP 必须满足

- 用户可以通过手机号 + 密码注册和登录。
- 用户可以记录收入和支出。
- 用户可以为每笔交易选择资金渠道和一个分类标签。
- 用户可以新增、编辑和隐藏自定义资金渠道。
- 用户可以新增、编辑和隐藏自定义分类标签。
- 用户可以编辑和软删除自己的交易。
- 用户可以查看月度收入、支出、结余、资金渠道统计和分类标签统计。
- PWA 可以安装到手机主屏幕。
- Vercel 生产环境可正常访问。
- Supabase RLS 阻止用户访问其他人的账本数据。

### 11.2 测试重点

- 未登录用户不能读取交易数据。
- 用户不能读取其他用户的账本和交易。
- 金额小于或等于 0 时不能提交。
- 未选择资金渠道或分类标签时不能提交。
- 删除交易后统计不再包含该交易。
- 隐藏资金渠道或分类标签后，历史交易仍可正常展示。
- 用户不能修改其他用户创建的资金渠道和分类标签。
- 收入、支出、资金渠道和分类标签统计口径正确。
